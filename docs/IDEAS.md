# Идеи для развития

Ниже — то, что можно добавить после того, как обязательные алгоритмы готовы.
Отсортировано по соотношению «польза / трудозатраты».

## Быстрые и заметные

1. **Экспорт H-дерева в PNG.** Кнопка на странице H-дерева:
   `RenderTargetBitmap` → `Save`. Пригодится для отчёта и презентации.
2. **Горячие клавиши.** Пробел — play/pause анимации, `R` — сброс,
   `1..4` — переключение задач. Мелочь, а на защите выглядит уверенно.
3. **Подсветка уровня рекурсии.** Легенда «цвет = глубина» рядом с полотном
   H-дерева (сейчас цвет интуитивно понятен, но лучше подписать).
4. **Сравнение перебора и D&C в таблице.** На странице ближайшей пары
   показывать рядом время и число сравнений обоих алгоритмов. Это самый
   наглядный результат лабораторной.

## Средние

5. **Анимация шагов судоку.** `BacktrackingSudokuSolver` уже вызывает `onStep`;
   остаётся складывать шаги в очередь и проигрывать с заданной скоростью
   (как анимация Ханоя). Получится красивая демонстрация backtracking.
6. **Анимация полосы в ближайшей паре.** `ClosestPairStep` передаёт `X0/X1`
   и пары; `PointsCanvas` уже умеет рисовать полосу и линию раздела.
7. **Дерево вызовов рекурсии.** Для H-дерева и Ханоя: узлы — вызовы,
   глубина — уровень. Можно рисовать отдельным окном или панелью.
8. **График производительности.** Замерять время ближайшей пары при
   n = 100, 200, 500, 1000, 2000 для перебора и D&C и строить график
   (Avalonia + простой `Path` по точкам). Хорошо смотрится в отчёте.

## Крупные

9. **Режим защиты.** Полноэкранное окно, крупные подписи, скрытие панели
   управления, автоматический прогон сценария (H-дерево → судоку → пара → Ханой).
10. **Светлая тема.** Сейчас тема тёмная; добавить переключатель и второй
    набор кистей в `Styles/LabTheme.axaml`.
11. **Сохранение состояния.** Условия судоку и наборы точек — в JSON,
    кнопки «Сохранить/Загрузить».
12. **CI.** GitHub Actions: `dotnet build` + `dotnet test` на каждый push;
    бейдж в README. Для учебной работы — приятный бонус.
13. **3D H-дерево.** Повернуть фрактал вокруг оси или добавить глубину по Z:
    получится эффектный вариант «фрактал в 3D» (но это уже сверх задания).

## Чего лучше не делать

- Не тащить тяжёлые UI-фреймворки (Material, ReactiveUI) ради одной кнопки.
- Не реализовывать чужие алгоритмы «за участника» — на защите спросят.
- Не менять публичные сигнатуры Core без необходимости: на них завязаны UI и тесты.
